# スローテックアプリ MVPスコープ

[画面遷移図.md](./画面遷移図.md) を基に、段階的な実装スコープを整理する。

## 考え方

- **核となる体験(30秒の静寂 → 一期一会の色 → 積み重なる絵)を、できるだけ早く検証できる形にする**ことを優先する。
- **デモで一番面白さを伝えたいのは、生成AIによる一期一会の掛け合い**。外部の生成AI(GitHub Copilot、ChatGPTなど)で事前に対話・音声を作り、アプリ内で再生するだけの形にすれば、フェーズ1の中で十分に体験させられる。
- カレンダー連携(フェーズ2)は、デモでは実装せずに言葉で説明するだけでもイメージが伝わりやすいため、後回しにする。

## フェーズ1(MVP):コア体験 + AI対話のデモ

通知やカレンダー連携がなくても、「30秒の静寂と一期一会の色」「AI対話の面白さ」を体験・検証できる最小構成。

- **トリガー**：手動のみ。キャンバス画面の「リセットタイムを始める」を押すことでのみ開始する。Googleカレンダー連携は行わない。
- **割込導入画面**：あらかじめ用意した固定の問いリストからランダムに1つ表示する。お気に入り/非表示の学習機能は無し(フェーズ2で対応)。
- **静寂の30秒**：仕様通り実装(水滴音・振動・光の脈動・スキップ導線・やめる導線)。ここは体験の核なので削らない。
- **出口**：4色固定パレットからのタップ、絵の具が広がる一期一会の演出、送り出し画面。ここも体験の核なので削らない。
- **そっと閉じる画面**：仕様通り実装。
- **キャンバス画面**：育成中の絵の表示、完成ボタン、ギャラリーへの導線。
- **ギャラリー**：完成済み3枚の表示のほか、**「サンプル」とラベル付けした絵1枚**を固定で置いておく。
  - ユーザー自身の絵(未対応)をタップしても何も起きない。AI対話はこの段階ではユーザー自身の絵に対して実装せず、サンプルの絵1枚のみ体験できるようにする。
  - サンプルの絵は、開発時に固定でデザインしておく(色の構成・順番・位置もあらかじめ決めたもの)。
  - サンプルの絵をタップすると、AI対話の体験(音声読み上げ+同期した文字の浮沈)を再生できる。この対話音声・テキストは、アプリ内でリアルタイムに生成AIを呼び出すのではなく、**外部の生成AI(GitHub Copilot、ChatGPTなど)に絵の内容を渡して事前に作っておいたもの**を再生するだけとする。実装コストを抑えつつ、デモで一番見せたい面白さを先行して体験できるようにする。

## フェーズ2:通知・自動トリガー

デモでの手応えが持てたら、Fastな人の生活に自動的に入り込む部分を実装する。

- Googleカレンダー連携、次の予定の5分前の通知トリガー(デモの段階では実装せず、口頭説明で補う)
- 通知文言のFast向け訴求のブラッシュアップ
- 問いのお気に入り/非表示の学習機能

## 将来的な発展:AI対話のアプリ内リアルタイム生成

フェーズ1のサンプル対話で手応えが持てたら、外部ツールでの事前生成ではなく、ユーザー自身の絵に対してもアプリ内で生成AI(LLM)・TTSをリアルタイムに呼び出す仕組みに置き換える。
